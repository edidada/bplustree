# 斐波那契堆（Fibonacci Heap）

## 1. 定义：二项堆 + 懒惰策略

**斐波那契堆** = 一组**最小堆序根树构成的森林**，且：

- **懒插入/懒合并**：insert、merge 只"挂链表、打标记"，不动结构——insert 摊还 $O(1)$、merge 摊还 $O(1)$；
- 结构规则远比二项堆松：树形只在 `delete-min`（提取最小）时才整理；
- 为了把 `decrease-key` 也做成摊还 $O(1)$，引入 **"削（cut）+ 级联削（cascading cut）+ 标记"** 规则：节点至多"被削过一个孩子"（失去第二个孩子时自己也上提到根表）。

## 2. 数据结构部件

- **根表（root list）**：所有树的根用循环双向链表串起，另存全局最小指针 `min`；
- 每个节点：key、父指针、孩子链、度（孩子数）、**标记位 mark**；
- **度表**：delete-min 用"按度数桶"合并同度树（辅助数组，大小 $O(\log n)$）。

## 3. 操作与摊还代价（核心结论表）

| 操作 | 实际 | 摊还 | 说明 |
|---|---|---|---|
| insert | $O(1)$ | $O(1)$ | 挂进根表，更新 min |
| merge | $O(1)$ | $O(1)$ | 根表合并 |
| find-min | $O(1)$ | $O(1)$ | min 指针 |
| delete-min | $O(D(n))$ | $O(\log n)$ | 把 min 的孩子全提为根，再**按度合并**成至多一棵每个度 |
| decrease-key | $O(1)$~削链 | **$O(1)$** | 削键→小于父则削离；父已标记→级联削 |

其中 $D(n)$ = 最大度数。**关键引理**：若一个"堆序树"的节点被削掉过 $\le 1$ 个孩子（mark 规则），那么度 $k$ 的树至少含 $F_{k+2}$ 个节点（**斐波那契数**——堆因此得名），故 $D(n) \le \log_\varphi n \approx 1.44\log_2 n$。

## 4. 势能分析要点（硕士/博士级）

定义势 $\Phi = t + 2m$（$t$=根表树数，$m$=被标记节点数）：

- **delete-min** 的"按度合并"使根表从 $D(n)+t'$ 收敛到 $D(n)$：实际 $O(D(n)+t)$，势降 $t-O(D(n))$ → 摊还 $O(D(n))=O(\log n)$；
- **decrease-key**：削一次实际 $O(1)$，势：级联削每次把父提根（$t$ +1）但若父被标记则 (2m) −2 → **净不增**，故每层削摊还 $O(1)$ → 总 $O(1)$ 摊还。

这套势函数是"懒惰结构摊还分析"的标准范本（与 splay 的势函数思想同类，[splay-tree.md](splay-tree.md)）。

## 5. 为什么重要

- **理论上最优**的"可并 + decrease-key"优先队列：支持 Dijkstra/Prim 时总代价
  $$ O(V\log V + E) $$
  比二叉堆的 $O((V+E)\log V)$ 更紧——decrease-key 摊还 $O(1)$ 是杀手锏；
- 配对堆（pairing heap）是其实践替身（实现简单、实测常更快，但摊还证明更微妙）；
- 教材位置：CLRS 第 19 章（斐波那契堆）、Fredman–Tarjan 1987 论文（曾用于加速最小生成树至 $O(m\log^*(n))$ 级）。

## 6. 与实际应用的分寸

- 常数大、指针多 → 生产环境少直接用斐波那契堆；多用于理论/证明"这个量可以摊还到 $O(1)$"；
- 面试/工程优先队列首选**二叉堆**；需要可并+减键且常数敏感用**配对堆/左偏堆**。

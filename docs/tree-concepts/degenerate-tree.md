# 退化树 / 斜树（Degenerate Tree, Skew Tree）

## 1. 定义

**退化树 / 退化二叉树**：每个内部节点至多只有一个孩子。二叉树语境下称为 **斜树（skew tree）**：

- **左斜树**：每个节点只有左孩子；
- **右斜树**：每个节点只有右孩子；
- 更一般的退化树允许左右交替，但始终"每层只有一个节点"，形态退化为一条 **链（path）**。

```
右斜树(链)                    左斜树
(a)                           (a)
  \                           /
  (b)                       (b)
    \                       /
    (c)                   (c)
```

## 2. 为什么"退化"很重要

退化树把 **"树"彻底退化为"链表"**：

- 高度 $= n-1$（最坏），任何从根到叶的查找/遍历代价 $O(n)$；
- 对二叉搜索树，若插入键有序（升/降序），BST 直接长成斜树 → 查找退化为顺序查找 → 这是所有**平衡树**（AVL/红黑/B 树）存在的原因；
- 递归深度也随之退化到 $n$，可能栈溢出（工程上深树要转迭代/显式栈）。

```
BST 依次插入 1,2,3,...,n（升序）
    1
     \
      2
       \
        3         ← 与链表演化相同
         \
         ...
```

## 3. 教学意义

- **本科**：二叉树的形态谱系为 完美(perfect) ↔ 完全(complete) ↔ 一般 ↔ **退化(斜)**，退化和满形是"最坏/最好"两个极端，用于推导高度界 $[\,\lceil\log_2(n{+}1)\rceil{-}1,\ n{-}1\,]$。
- **硕士**：平衡条件（AVL 的平衡因子、红黑树的黑高）本质上就是"禁止退化的合理近似"；数据被有序批量插入时（如数据库灌数据），若不加平衡/分裂，结构必然斜化——这也是磁盘 B 树要"插入即分裂保持满"的现实动机。
- **算法设计**：某些结构**允许退化**但有均摊保证（splay 树、treap 最坏形如链但概率/摊还可控），是"结构最坏 vs 摊还最好"的经典对照。

## 4. 判别与应用

- 判别斜树：DFS 检查是否每点至多一个非空孩子。
- 链式退化在**卡特兰极值、动态规划顺序**（括号匹配栈深）中有对应模型：栈深最大即斜。
- 注意不要把"斜树"与"左偏堆/右偏堆"混同：左偏树是**有意不平衡**的堆合并结构（[leftist-heap.md](leftist-heap.md)），其"左偏"是有序分布、最坏 NIL 路径受控，并非退化。

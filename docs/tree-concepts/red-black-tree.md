# 红黑树（Red-Black Tree, RBT）

## 1. 定义

红黑树是每个节点带**红/黑**颜色的二叉搜索树，满足四条不变量：

1. 每个节点是红的或黑的；
2. **根是黑的**；
3. 每个叶（NIL 空指针，视为**黑色哨兵**）是黑的；
4. **红规则**：红节点的两个子节点都是黑的（即不能出现"红-红"父子）；
5. **黑高一致**：从任一节点到其所有叶（NIL）的路径上**黑节点数相同**，该数称该节点的**黑高（black-height）** $\mathrm{bh}(v)$。

```
            (B)30
          /      \
      (R)20      (B)40
      /   \      /   \
   (B)10 (B)25 (B)35 (R)50
   /  \                       NIL 全黑省略
 (NIL)(NIL)
每条根到 NIL 路径黑节点数=3（含NIL）：bh(root)=3
```

## 2. 黑高 ⇒ 高度上界

关键引理（CLRS 红黑树章 Lemma 13.1）：

- 以 $v$ 为根的子树**至少含 $2^{\mathrm{bh}(v)}-1$** 个内部节点（归纳）；
- 由红规则，根到叶路径上红节点不超过一半 ⇒ 高度 $h \le 2\cdot\mathrm{bh}(root)$；
- 故含 $n$ 个内部节点的红黑树高 $h \le 2\log_2(n+1) = O(\log n)$。
（比 AVL 的 1.44 界松，但换来维护代价低——见 §4。）

## 3. 与 2-3-4 树的对应（必懂本质）

把每个**红节点与其黑父"绑定"为一个 4-结点/3-结点**，可把红黑树还原成一颗 2-3-4 树（[23-tree.md](23-tree.md)）：

```
2-3-4 结点 (k1)        红黑树等价表示（黑父+红子）
      (k1)                  (B) k1
    /  |  \                 /      \
  /    |    \            (R) k1L    k1R
若 k1 有两个键 k1L<k1<k1R  → 左子红、右子红  （左红 = 4结点左键）
```

- 红黑树的**插入/删除修复** = 2-3-4 树的**分裂/合并**的等价模拟；
- 为什么根必须黑、红子不可连红：正是 2-3-4 结点"键数 ≤3、只含一个黑键"的翻译。

## 4. 操作与复杂度（结论先行，细节看教材）

| 操作 | 旋转次数 | 代价 |
|---|---|---|
| 查找 | 0 | $O(\log n)$ |
| 插入 | ≤2 次旋转 + $O(\log n)$ 次变色 | $O(\log n)$ |
| 删除 | **≤3 次旋转** + 变色/调整 | $O(\log n)$ |

- 插入修复三情况（叔红 → 变色上移；叔黑且 zigzag → 双旋；叔黑且直链 → 单旋）与删除四情况（兄弟红/黑、侄子红/黑组合）建议配 2-3-4 图理解，硬背易错。
- **与 AVL 的取舍**：红黑树牺牲更松的高度界换"删除/插入至多 3 次旋转"；实际查改均衡场景红黑更稳。经典使用：Linux 内核 rbtree、C++ std::map、Java TreeMap/HashMap 树化桶、Nginx 定时器。

## 5. 工程细节

- **NIL 哨兵**：用单一共享 NIL 节点代替大量空指针（节省内存、统一代码）——"哑节点/哨兵"思想（[tree-terminology.md](tree-terminology.md)）；
- 颜色可用节点最低位压缩存储；
- 左倾红黑树（LLRB）是教学简化版：把"红子必须左倾"使红黑树 ↔ **2-3 树**（非 2-3-4）一一对应，插入实现更短（Sedgewick 用于教材/Go 类库）。

## 6. 历史与变体

- 1972 Bayer 提出"对称二叉 B 树"，1978 Guibas–Sedgewick 定型为红黑树；本质是 **B 树族**（4 阶特化）的内存特例，与磁盘 B 树在"分裂/合并"上同源——因此红黑树也被称为 **2-3-4 树的二叉树表示**。
- 变体：AA 树（简化红规则到"无左红子+无连续红"）、LLRB。

# 线索二叉树（Threaded Binary Tree）

## 1. 动机

$n$ 个节点的二叉树用左右孩子链表表示时共有 $2n$ 个链域，但实际非空指针只有 $n-1$ 个（树有 $n-1$ 条边），**空链域 $n+1$ 个被浪费**。线索二叉树把这些空指针利用起来，指向前驱/后继，以**加速遍历、节省栈**。

## 2. 线索化定义

按某种遍历次序，把空链域改为：

- **前驱线索（thread）**：若 $v$ 无左孩子，`left` 指向 $v$ 在**该遍历序**下的**前驱**；
- **后继线索**：若 $v$ 无右孩子，`right` 指向 $v$ 在**该遍历序**下的**后继**。

因为每个节点需要区分"指针指向孩子还是线索"，需加两个标志位（经典结构）：

```c
struct tbt_node {
    key_t key;
    struct tbt_node *left, *right;
    bool ltag, rtag;   /* 0=孩子指针，1=线索 */
};
```

## 3. 中序线索树（最常见）

中序线索二叉树中，所有"空右孩子"改成指向**中序后继**，"空左孩子"改成指向**中序前驱**：

```
中序序列: B A C   （根 A，左子 B，右子 C）
     (A)
    /   \
  (B)   (C)

B.left  → NIL → 指向前驱（无，可为哑头/空）
B.right → A（中序后继）
C.left  → A（中序前驱）
C.right → NIL（中序无后继）
```

- 没有左右孩子的节点，其左右指针全成线索；
- **带头结点（head）** 的线索树把第一个节点前驱、最后一个节点后继都指向头结点，便于双向遍历。
- 头结点是"哨兵"思想：根的双亲化（见 [tree-terminology.md](tree-terminology.md) 的"哑节点"）。

## 4. 遍历：不需要栈的 $O(1)$ 空间中序遍历

```c
/* 求中序后继 */
struct tbt_node *inorder_next(struct tbt_node *v) {
    if (v->rtag == 1) return v->right;          /* 线索直达 */
    v = v->right;                                /* 右子树的最左节点 */
    while (v && v->ltag == 0) v = v->left;
    return v;
}
/* 从中序首节点开始反复调用 inorder_next 即完成 O(n) 中序遍历，无需栈/递归 */
```
- 先序线索树易求"后继"，但求前驱需要线索与父信息配合；中序线索对**双向遍历**最自然（前驱/后继都可 $O(1)$ 得）；
- 后序线索实现最繁琐（求后继可能要用 parent），教科书一般只详细展开中序。

## 5. 复杂度与工程意义

- 空间：省下的 $n+1$ 个空指针变为线索（标志位有少量额外开销，纯指针存储未必省内存，但获得的是**遍历免栈**与**前驱后继 $O(1)$**）；
- 时间复杂度：线索化的中序遍历 $O(n)$，且**无需递归栈**，深度极深（退化树）时不栈溢出；
- 思想延伸：
  - **Morris 遍历**：临时改动指针实现 $O(1)$ 空间遍历后恢复，是现代"免栈遍历"标准解法；
  - B+ 树的**叶兄弟链**（叶间 prev/next 指针）本质是"叶子级线索"，让范围查询不用回溯祖先——[bplus-tree.md](bplus-tree.md) 会指出这点与线索树的亲缘关系。

## 6. 教材位置

- **本科**：严蔚敏教材将线索树作为"空链域利用 + 遍历加速"案例，考中序线索化算法题（递归/栈转线索）。
- **更高视角**：线索 = "在指针上附加信息以去除递归依赖"；与此同族的技术还有哨兵节点、哑头、前驱指针（三叉链）等工程技巧。

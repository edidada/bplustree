# 2-3 树与 2-3-4 树

## 1. 多路搜索树的定义（先于 B 树）

**2-3 树**：每个节点含 **1 或 2 个键**，相应有 **2 或 3 个孩子**：

- **2-结点**：1 键 2 子（像 BST 节点）；
- **3-结点**：2 键 3 子，设键 $k_1<k_2$，则左子树 < $k_1$、中子 $\in(k_1,k_2)$、右子树 > $k_2$。

**2-3-4 树**：额外允许 **4-结点**：3 键 4 子。

```
2-3 树示例
            [30 | 60]          ← 3-结点
           /    |     \
      [10|20] [40|50] [70]     ← [10|20] 3-结点，[70] 2-结点
```
性质：
1. 所有叶在同一层（**完美平衡**）；
2. 每个内部节点孩子数 = 键数 + 1；
3. 查找：节点内二分 + 选子树下降。

## 2. 插入：先下探、必要时向上分裂（自底向上生长）

插入总是先在**叶结点**放键；若该结点键数超限（3-结点再加 = 4 键，2-3 树），**分裂**：中间键上提给父，左右变两结点；父若也满则继续上提，最坏分裂到根——**根分裂树长高**：

```
向 [40|50] 插入 45（2-3 树）→ 变 [40|45|50] 超限
      [45]  上提到父，剩下 [40] 与 [50]
```
```
2-3-4 树: 向 4-结点 [20|40|60] 插入 50  → 分裂 40 上提
         [40]
        /  |  \
   [20]   [50]  [60]??  （示意；正确分裂 40 上提，20 与 60 分家）
```

关键结论：**树从根部向上长高**（split 只影响祖先链）；所有叶保持同层 ⇒ 高度始终 $O(\log n)$，且与插入顺序无关。

## 3. 删除：借位与合并

删除要维持"每个非叶节点键数 ≥ 下限"：

- 删叶中的键，键数不够（2-3 树 2-结点变 0 键）时：
  - **借位（rotation/borrow）**：兄弟有多余键，父键下移 + 兄弟键上移（保持中序）；
  - **合并（merge/fusion）**：兄弟也穷，把父的一个键拉下来与两兄弟并成 3/4-结点；
  - 父因此可能再不够 → 逐层向上，最坏根合并树变矮。

这和 B 树（[b-tree.md](b-tree.md)）删除的借/并**完全一致**——2-3 树就是 **$m=3$ 的 B 树**，2-3-4 树即 **order-4 B 树**（"B 树的一种实现"）。

## 4. 为什么现在几乎见不到直接的 2-3-4 树

- **节点大小不一**（1-3 键）→ 工程上要么浪费存储要么要动态分配，实现丑；
- 但它是理解两大工业结构的**中间抽象**：
  - **红黑树 = 2-3-4 树的二叉树表示**（把多键结点拆成"黑父 + 红子"，[red-black-tree.md](red-black-tree.md)）；
  - **B/B+ 树 = 键数固定的 2-3-4 树放大版**（order $m$，磁盘块大小决定），[b-tree.md](b-tree.md)。

## 5. 教学层级

- **本科（严蔚敏/邓俊辉）**：2-3 树作为"多路平衡查找树"引入，为 B 树打基础；常手工演练分裂/合并。
- **硕士**：红黑树与 2-3-4 树的等价证明、B 树是 2-3-4 的一般化（order m），三者统一为"多路搜索树的平衡维护"。
- 高级视角：2-3 树的分裂合并即 B 树的特例；"底部分裂、顶部长高"是所有**页式平衡结构**的公共模板。

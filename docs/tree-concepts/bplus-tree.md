# B+ 树（B+ Tree）

> 本仓库的实现对象（`lib/bplustree.c`，磁盘 B+ 树）。配合 [b-tree.md](b-tree.md) 阅读，多路搜索树的性质在此不再重复。

## 1. 与 B 树的差异（B+ 树的定义特征）

1. **内部节点只存键（不存数据），且键用于"路由"**：每个内部键 = 其右子（下一块）的**最小键**；
2. **所有数据（key+value/记录）都存放在叶节点**；
3. **叶节点之间用指针（prev/next）串成链表**——叶链；
4. 内节点的孩子数 = 键数 + 1（与 B 树同），但因其键更小（不带数据），一个磁盘页能装更多路由键 → **更高的扇出（fan-out）**。

```
                      [ 40 | 80 ]            内部节点（只存路由键）
                     /    |     \
         [10|20|30]    [50|60|70]   [90|...]  叶节点（存全部键值对）
              |  -----------  ----------
              v        v         v
         ── 叶链 prev/next 双向串联，范围扫描沿链右移 ──
```
本仓库实现即此形态：内节点存 `key + child 偏移`，叶节点存 `key + data` 且叶间有 `prev/next` 兄弟偏移（见 `bplus_industrial_comparison.md` 第 1 节矩阵）。

## 2. 为什么数据库/文件系统偏爱 B+ 而非 B

| 优势 | 原因 |
|---|---|
| **范围查询高效** | 找到下界叶后沿叶链顺序扫描，无需回溯父节点（[b-tree.md](b-tree.md) 的范围查询要反复爬树） |
| **I/O 更少** | 内节点瘦 → 扇出大 → 同页大小下高度更低 |
| **缓存友好、顺序 I/O** | 叶链天然支持区间预读；B 树范围内点在叶与内节点间跳转 |
| **删除更简单** | 只删叶（内键是路由副本，欠载时借/并的是叶；内节点键可懒更新） |
| **叶即数据页/聚簇** | 数据库把"叶页"当数据页直接存记录，内部页当纯索引页（InnoDB 聚簇索引） |

代价：**单键点查**比 B 树略多一层下探的差异可忽略；但内存占用"内部索引 + 叶数据"双份路由（对非聚簇场景）。

## 3. 结构细节（工程级，对齐本仓库实现）

- **块即节点**：block_size（如 4096B）同时约束内/叶节点的键容量。本仓库初始化打印的 `node order`/`leaf entries` 即由此推导。
- **根**：B+ 树最初仅一个叶；内节点分裂沿向上路径，根分裂 → 高度 +1。
- **叶链与范围查询**：`get_range(k1,k2)` = 二分定位 $k1$ 所在叶 → 沿 `next` 右移收集，直到越过 $k2$。本仓库实现按"整树叶键皆有序、叶间单调"实现。
- **元数据与空闲管理**：磁盘树需要记录"根节点位置、文件长度、空闲块表"。本仓库用 `.boot` 元数据文件存 root/block_size/file_size/free_blocks（16 进制明文），`free_blocks` 回收分裂/合并产生的空块（类比数据库 freelist）。
- **缓存**：真正的磁盘树几乎必须配页缓存。本仓库仅有 5 块暂存缓冲；SQLite/LMDB 是完整页缓存（工业对比见 `bplus_industrial_comparison.md`）。
- **兄弟指针**：删除时"先看兄弟能否借、不能则与兄弟合并"——与 [23-tree.md](23-tree.md) 完全同构，只是节点大。

## 4. 复杂度与参数直觉

设叶存 $L$ 键/块、内节点存 $I$ 键/块（$I>L$，因不带数据）：

- 高度 $h\approx \log_I(n/L)+1$；
- 本仓库实测：4096B 块、$I=338$ 时 $10^6$ 键高约 3 层；顺序插入约 43 万键/s（机器相关，见对比文档实测节）。

## 5. 操作速查

| 操作 | 行为 |
|---|---|
| 查找 key | 根起沿路由键二分下行至叶，叶内二分 |
| 插入 | 定位叶→插入→叶满分裂（提中间键复制到父）→父满上溯分裂 |
| 删除（=本仓库 put(key,0)） | 定位叶删键→低于半满借兄弟/合并叶→父键欠载借/并（内键需更新路由最小键） |
| 范围 | 叶链顺序扫描 |
| 构建 | 自底向上 bulkload：排序键按块打包更高效（顺序插入已接近） |

## 6. 变体

- **B* 树**：分裂更"懒"（先与兄弟重分配、2/3 满才分裂），空间利用率更高；
- **前缀压缩 B+**：内部键存公共前缀以增扇出；
- **LSM-tree**：写优化的替代（B+ 是读优化/范围优化），数据库选型时对比；
- 分支预测/缓存优化的内存 B+（B+ 树也常用作内存多路索引）。

# 伸展树（Splay Tree）

## 1. 定义与直觉

**伸展树**是一种"**自我调整**"二叉搜索树：**每次访问（查找/插入/删除）都把被访问节点通过旋转提升到根**（称作 **splay 操作**），路径上的结构随之重组：

- 无平衡因子、无颜色、无显式高度约束——是"**每次访问都改变形状**"的自组织结构；
- 频繁访问的节点会靠近根，**后续访问更快**（访问局部性收益）；
- 最坏单次操作仍是 $O(n)$（如一直访问同一个刚被移到根的叶的极端构造），但摊还 $O(\log n)$。

## 2. 三种 splay 情形（由 z 到根 x 的两级旋转组合）

沿访问路径从下往上对"x、父 p、祖父 g"处理，直至 x 到根：

| 情形 | 形态 | 动作 |
|---|---|---|
| zig | x 的父就是根 | 单旋转 x 上移（结束） |
| zig-zig | x 与 p 同为左子（或同为右子） | 先旋 p 再旋 x（同向双旋，**扁平化关键**） |
| zig-zag | x 与 p 异侧 | 先旋 x 再旋 x（双向双旋，同 AVL 双旋） |

```
zig-zig:   g            先右旋 p，再右旋 x
          /            x 到顶，链条被"折叠"
         p
        /
       x
```
与普通单旋上移的区别：**zig-zig 先旋父**，把长链折叠成"之"字形扁平结构，这保证了后续摊还界。

## 3. 摊还分析（硕士重点：访问引理）

定义势函数 $\Phi=\sum_v \log(\text{size}(v))$（size 为子树规模）。**Splay 引理**：对节点 $x$ 做一次 splay 的摊还代价至多

$$ 3\log\frac{\text{size}(T)}{\text{size}(x)} + 1 = O(\log n) $$

由此得到三个著名结论（每次操作都先 splay，故都为摊还 $O(\log n)$）：
1. 查找 $O(\log n)$ 摊还；
2. 插入/删除 $O(\log n)$ 摊还；
3. **顺序访问引理**：若以递增序访问全部 $n$ 个键（每次访问后 splay），总共 $O(n)$ —— 比每次 $\log n$ 更紧，反映"树被访问逐步展平成近线性结构"。

## 4. 优缺点

**优点**：
- 无需存储任何平衡信息（内存省、实现简洁）；
- 摊还 $O(\log n)$，且**缓存/访问局部性**极好（热数据常驻根）；
- 支持"访问后自动重排"，适合 LRU 类场景（如缓存、AC 自动机?不，AC 用 trie；典型如 Linux 用户页表?现多用红黑）。

**缺点**：
- 单次可能 $O(n)$（实时性要求高、不能容忍长尾延迟的场合不适合）；
- 只读查找也会改树 → 并发/只读共享场景需要额外同步（树会被写）；
- 常数与旋转开销有时高于 AVL/红黑。

## 5. 变体与延伸

- **Link-Cut Tree（动态树）**：把树按重路径剖分后用 splay 森林维护，支持动态连边/换根/路径查询 $O(\log n)$ 摊还——splay 的"单点访问摊还"是 LCT 正确性的基础（博士/竞赛进阶，见 [lca.md](lca.md) 提及的动态树方向）。
- 与随机化对照：treap 用随机堆序达到 $O(\log n)$ 期望，splay 用"被访问者变根"达到 $O(\log n)$ 摊还——**结构决定论 vs 随机化**的两种范本（[treap.md](treap.md)）。

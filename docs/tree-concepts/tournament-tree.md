# 胜者树 / 败者树（Winner / Loser Tree，锦标赛树）

## 1. 定义

**胜者树（winner tree）** 与 **败者树（loser tree）** 是用于**从 k 路输入中反复取最小元素**的完全二叉树（竞赛/锦标赛树）。叶节点代表各路输入，内部节点记录一次比较的胜者/败者：

```
胜者树（取最小）：         败者树（内部存败者，根上再叠一个最小）
      (min)                    [冠军 min 单独记录]
     /     \
  (a胜)   (c胜)       内部只记"这场谁输了"，胜者路径在比赛时从叶向上用兄弟比较推得
  /  \    /  \
 a   b   c   d        败者树重建代价略小：新值只需沿固定路径与败者比
```

- 完全二叉树结构 → 可用**数组**存放（叶从下标 $k$ 起放 k 路元素）；
- 单场淘汰逻辑（锦标赛）得名；
- 与 [binary-heap.md](binary-heap.md) 的区别：堆是"自顶向下维护极值"，锦标赛树是"叶子替换后从叶向根重赛"，**更适合外部归并的场景**。

## 2. 经典应用：外部排序的多路归并

当数据量超过内存，排序分两阶段：
1. **生成初始归并段（run）**：内存中排序后写回磁盘；
2. **k 路归并**：同时打开 k 个归并段，每轮取 k 段中最小者输出。

朴素 k 路归并每轮比较 k−1 次；用败者树每轮只需 $\lceil\log_2 k\rceil$ 次比较（淘汰赛层数），总代价从 $O(kn\log n)$ 类降到 $O(n\log k \cdot \log n)$ 级别（外层 log 归并轮数）。
- **败者树优于胜者树的点**：某路元素输出后从该段读入新元素，只需与其"曾经输给的祖先"比较即可确定新冠军路径——**每轮只沿一条根路径重赛**，比较次数固定为树高。

## 3. 胜者树 vs 败者树（细看）

| | 胜者树 | 败者树 |
|---|---|---|
| 内部节点含义 | 该子树胜者 | 该子树"败者"（胜者在更上层） |
| 冠军位置 | 根 | 独立冠军变量 + 内部存败者 |
| 替换一个叶子后 | 沿叶到根重算（遇到对手） | 只需与固定祖先链上的败者比，更规则、便于汇编优化 |
| 外排序历史 | 早期多用 | TAOCP 时代起标准实现 |

## 4. 各层级视角

- **本科（严蔚敏等）**：作为"外部排序"章节讲解；需手工画败者树并写出"谁与谁比"的调整过程。核心考点：败者树高度 = $\lceil\log_2 k\rceil$，调整一次 $O(\log k)$。
- **硕士（DB 实现）**：多路归并是排序算子的核心；现代 DB 用**堆 + 谓词下推**做归并，原理等价但工程上败者树在"外部性"上更优。
- **博士/更广**：锦标赛树也是**选择问题的对弈树**（找第 k 小、同时找最大最小、锦标赛淘汰比较次数下界 $n+\lceil\log_2 n\rceil-2$ 找第二大——"冠军输给过的人里再比"）。这个"冠军必须输给过别人"思想也出现在树形锦标赛结构中。

## 5. 注意辨析

- 哈夫曼树每次取两个最小（用堆，非锦标赛树），见 [huffman-tree.md](huffman-tree.md)；
- 胜者/败者树与 B 树无关（别把"多路归并"的 k 与 B 树阶 m 混同，但两者都追求"减少访问次数"：前者少比较、后者少 I/O，见 [b-tree.md](b-tree.md)）。

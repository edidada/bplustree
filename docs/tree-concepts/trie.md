# 字典树 / Trie（前缀树、Patricia、基数树、双数组）

## 1. 定义

**Trie（单词查找树）**：按**字符（或比特）沿路径分支**的多叉树，用于存储字符串集合：

- 根到某节点路径上的边字符拼接 = 该节点对应的**前缀**；
- 每个节点可有至多"字母表大小"个子节点（一般用数组/哈希表/稀疏结构存）；
- 用"终止标记（is_end）"标出哪些节点是一个完整词。

```
插入: cat, car, dog, do

        (·)
      /    \
    c       d
    |       |
    a       o
   / \      |
 (t  r)    (g)
  |   |     |
  ●   ●     ●      ●=词尾
cat car    do dog
```
优点：**按前缀共享存储**；查找/插入复杂度 $O(\text{len}(s))$，与集合大小 $n$ 无关（对比 BST 的 $O(\log n)$ 次比较）。
缺点：每个字符一个节点，可能比哈希表吃内存。

## 2. 变体族谱（术语最乱的族，按英文记）

| 名称 | 特征 |
|---|---|
| **Trie / 前缀树** | 边=字符，朴素多叉 |
| **压缩 Trie（compressed trie / PATRICIA）** | 把"单链无分支"路径合并成一条边带子串（减少节点数） |
| **基数树（radix tree）** | 以比特/固定基数切分键的压缩 trie（Linux 内核 radix tree、路由表） |
| **双数组 Trie（double-array）** | 用两个数组紧凑表示转移（分词库 jieba、Aho–Corasick 自动机常用） |
| **字典树** | "trie" 的中文通译（取 re**trie**val 词根，读作 "try"） |
| 哈夫曼树 | 一类**特定前缀码**的二叉树，本质也是一种"叶在终点的 trie"（[huffman-tree.md](huffman-tree.md)） |

## 3. 经典操作与扩展

| 操作/扩展 | 说明 |
|---|---|
| 插入/查找/删除 | $O(L)$（$L$=字符串长） |
| 前缀查询 / 前缀计数 | 走到前缀终点，统计子树标记数（每节点存 count 即可 $O(1)$ 答） |
| 字典序排序 | trie 前序遍历 = 字典序；替代排序 |
| 最长公共前缀 | 找最深共同祖先（LCA 思想的 trie 版，[lca.md](lca.md)） |
| 自动机：Aho–Corasick | trie + fail 指针（失配跳转），多模式串匹配 $O(n+\text{匹配数})$，是**确定性自动机 + trie**的完美结合 |
| 01-Trie | 按比特建立二叉树，做最大异或对/第 k 大异或（竞赛热门） |

## 4. 复杂度对比（字符串集合检索）

| 结构 | 查找 | 额外优点/缺点 |
|---|---|---|
| 哈希表 | $O(L)$ 期望 | 无法前缀查询、无序 |
| 平衡 BST | $O(L\log n)$ 比较 | 支持有序范围但每步全串比较 |
| **Trie** | $O(L)$ 严格 | 前缀/有序/自动机扩展，内存大 |

## 5. 教学与理论视角

- **本科（严蔚敏/邓俊辉）**：作为"串的存储/检索"结构；工程词汇表、拼写检查、输入法候选。
- **硕博（DB/信息检索/算法）**：
  - trie 是**确定性有限自动机（DFA）**的树形表示 → 与正则匹配、Aho–Corasick 统一；
  - 压缩 trie ↔ 后缀树的关系：后缀树 = 某字符串**全部后缀**的压缩 trie（[suffix-tree.md](suffix-tree.md)）；
  - 基数树用于路由最长前缀匹配（LPM，网络博士/工程方向）；
  - Patricia 压缩使 trie 在"键极长且共享前缀多"时空间 $O(\text{总字符数})$ 到 $O(\text{节点数+边标签})$。

## 6. 实现要点

- 子表：数组（快但按字母表浪费） vs 哈希映射 vs 排序数组二分 vs 双数组；
- 结束标记之外常存 `count`（以该前缀开头的词数）支持快速统计；
- 内存大是头号工程问题 → 压缩/基数/双数组是解决路线。
